# راه‌اندازی قانونی ابزارهای تولید

تاریخ بازبینی: 2026-11-21

## این مخزن چه چیزی فراهم می‌کند؟

- `tools/manifest.json`: فهرست ماشین‌خوان ابزارها، دسته‌بندی، لینک رسمی، نقش در پروژه و وضعیت توصیه.
- `docs/TOOLS_CATALOG.md`: کاتالوگ فارسی با توضیح و لینک‌های دریافت.
- `docs/PRODUCTION_PIPELINE.md`: مسیر پیشنهادی تولید asset و خروجی‌های runtime.

**هیچ installer، فایل اجرایی تجاری، شماره‌سریال، حساب کاربری یا لایسنس در مخزن قرار نمی‌گیرد.** وضعیت همهٔ موارد در manifest برابر `catalogued_not_installed` است؛ یعنی فقط در مخزن ثبت شده‌اند و نصب محلی آن‌ها تأیید نشده است.

## ترتیب پیشنهادی نصب

برای نسخهٔ مرورگری فعلی که با Three.js ساخته شده، نصب همهٔ ابزارهای فهرست‌شده نه لازم است و نه توصیه می‌شود. ابزارهای هم‌نقش جایگزین هم هستند؛ چند موتور فیزیک، چند پایگاه داده و چند ابزار مدل‌سازی را هم‌زمان وارد پروژه نکن.

1. **ساخت مدل سه‌بعدی:** Blender. خروجی اصلی را GLB/glTF نگه دار.
2. **تکسچر و تصویر:** یکی از Krita یا GIMP؛ در صورت نیاز Inkscape برای SVG.
3. **نقشه:** Tiled یا LDtk فقط اگر واقعاً از tile/level data استفاده می‌شود.
4. **صدا:** Audacity برای پاک‌سازی و برش؛ Bfxr یا ChipTone برای افکت‌های ساده.
5. **فیزیک:** ابتدا فیزیک فعلی Three.js را ارزیابی کن؛ سپس Rapier را در branch آزمایشی benchmark کن.
6. **UI:** Figma یا Penpot؛ Rive فقط در صورت نیاز واقعی به انیمیشن تعاملی.
7. **بک‌اند:** برای نسخهٔ آفلاین هیچ سرویس backend نصب نکن. در صورت تعریف قابلیت آنلاین، ابتدا یک گزینه مانند Supabase/PostgreSQL را طراحی و threat-model کن.
8. **ابزارهای تخصصی و تجاری:** Maya، 3ds Max، ZBrush، Cinema 4D، Houdini و ابزارهای مشابه فقط با نیاز تولید واقعی و مجوز معتبر اضافه شوند.

## روش دریافت و نصب

1. از لینک رسمی هر ابزار در کاتالوگ یا manifest وارد وب‌سایت ناشر شو.
2. سازگاری سیستم‌عامل و سخت‌افزار را بررسی کن.
3. شرایط مجوز، استفادهٔ تجاری، محدودیت‌های asset و مجوز runtime را جداگانه بخوان.
4. installer را فقط از ناشر یا فروشگاه رسمی دریافت کن؛ checksum/signature را در صورت ارائهٔ ناشر بررسی کن.
5. نسخهٔ نصب‌شده را در گزارش ساخت یا inventory تیم ثبت کن. فایل installer را commit نکن.
6. پروژه‌های منبع مانند BLEND، KRA، PSD یا فایل‌های DAW را از خروجی‌های runtime جدا نگه دار.
7. برای asset شخص ثالث، نام خالق، منبع، تاریخ دریافت، نسخه و مجوز را در `THIRD_PARTY_NOTICES.md` ثبت کن.

## استانداردهای تبادل داده

| نوع دارایی | فرمت پیشنهادی |
|---|---|
| مدل، متریال و انیمیشن سه‌بعدی | GLB / glTF 2.0 |
| تکسچر | PNG یا WebP بهینه‌شده |
| تصویر برداری UI | SVG |
| صوت منبع | WAV |
| صوت runtime | OGG |
| دادهٔ نقشه | JSON با schema مستند |
| تنظیمات پروژه | JSON با نسخه‌بندی schema |

## محدودیت‌های مخزن

- فایل‌های نصبی، crack، serial، credential، token و کلیدهای API را commit نکن.
- مجوز Blender یا هر asset مجزا، مجوز سایر برنامه‌ها یا assetها را پوشش نمی‌دهد.
- از Git LFS فقط برای فایل‌های منبع بزرگ و ضروری استفاده کن و quota مخزن را بررسی کن.
- dependency runtime باید نسخهٔ دقیق و منبع قابل اعتماد داشته باشد؛ از `latest` بدون pin نسخه در build نهایی پرهیز کن.
- برای استفادهٔ تجاری، مجوز ابزار، افزونه، فایل مدل، فونت، تکسچر، انیمیشن و sample صوتی باید جداگانه بررسی شود.

## وضعیت نامشخص یا نیازمند بررسی

این کاتالوگ لینک‌های رسمی و وضعیت کلی را ثبت می‌کند؛ **نصب، سازگاری نسخه و حق استفادهٔ تجاری هیچ ابزار/asset را خودکار تأیید نمی‌کند.** وضعیت محصولات در طول زمان تغییر می‌کند. پیش از شروع production، release notes و terms رسمی همان نسخه را دوباره بررسی کن.
