# خط تولید پیشنهادی Police Simulator 3D

## هدف این سند

این پروژه در حال حاضر یک نمونهٔ اولیهٔ مرورگری مبتنی بر Three.js است. بنابراین ابزارهای تولید دارایی باید خروجی‌های استاندارد و قابل‌استفاده در مرورگر تولید کنند. نصب همهٔ ابزارهای فهرست‌شده نه لازم است و نه یک معماری فنی محسوب می‌شود.

## مسیر اصلی پیشنهادی

| بخش | انتخاب اصلی | خروجی/استاندارد |
|---|---|---|
| مدل‌سازی و صحنه | Blender | GLB/glTF 2.0 |
| تکسچر و تصویر | Krita یا GIMP | PNG / WebP |
| گرافیک برداری | Inkscape | SVG |
| نقشه و layout | Tiled یا LDtk | JSON و دادهٔ نقشه |
| انیمیشن سه‌بعدی | Blender؛ Mixamo فقط برای نمونه‌های مجاز | glTF animation |
| انیمیشن UI | Rive در صورت نیاز واقعی | فایل runtime سازگار با وب |
| صدا | Audacity + ChipTone؛ DAW فقط در صورت نیاز موسیقی | WAV برای منبع، OGG برای runtime |
| فیزیک | Rapier برای مسیر وب، پس از آزمون | package نسخه‌بندی‌شده |
| UI/UX | Penpot یا Figma | مشخصات طراحی و asset |
| بک‌اند | فعلاً هیچ‌کدام؛ در صورت نیاز آنلاین، Supabase + PostgreSQL را ارزیابی کنید | API سمت سرور |

## ابزارهای جایگزین، نه الزامات هم‌زمان

Maya، 3ds Max، ZBrush، Cinema 4D، Houdini و SketchUp می‌توانند در صورت نیاز تخصصی به خط تولید اضافه شوند؛ اما برای جلوگیری از ناسازگاری، هر asset باید در نهایت به فرمت تبادل مورد توافق، ترجیحاً GLB/glTF، صادر شود.

World Machine و Gaea برای تولید زمین‌اند. ProBuilder وابسته به Unity و Chaos Physics وابسته به Unreal Engine هستند؛ در نسخهٔ فعلی Three.js نباید آن‌ها را به‌عنوان dependency اجرایی فرض کرد. Box2D دوبعدی است و MuJoCo ابزار شبیه‌سازی پژوهشی/مفصلی است؛ هیچ‌کدام انتخاب پیش‌فرض فیزیک خودرو برای این پروژه نیستند.

## ساختار پوشه‌های پیشنهادی

```text
assets/
  models/
    vehicles/
    buildings/
    props/
    characters/
  textures/
  animations/
  audio/
  ui/
  maps/
docs/
  TOOLS_CATALOG.md
  PRODUCTION_PIPELINE.md
```

فایل‌های منبع قابل‌ویرایش (مثلاً BLEND، PSD، KRA و فایل پروژهٔ صوتی) را در کنار خروجی runtime نگه دارید، اما آن‌ها را با فایل‌های لازم برای اجرای مرورگر اشتباه نگیرید. برای فایل‌های حجیم از Git LFS استفاده کنید و پیش از فعال‌سازی، محدودیت‌های حساب و فضای ذخیره‌سازی را بررسی کنید.

## کنترل کیفیت دارایی

1. مقیاس، جهت محور، نقطهٔ مبنا و نام‌گذاری فایل‌ها باید ثابت باشد.
2. مدل‌ها باید دارای UV و تکسچرهای بهینه باشند؛ تعداد چندضلعی و اندازهٔ تکسچر بر اساس بودجهٔ عملکرد تعیین شود.
3. خروجی GLB در یک صحنهٔ آزمایشی Three.js بازبینی شود؛ فقط سالم بودن فایل در نرم‌افزار سازنده کافی نیست.
4. انیمیشن‌ها باید از نظر skeleton، نام‌گذاری clip، root motion و loop بررسی شوند.
5. صداها باید از نظر مدت، بلندی، clipping، فرمت و حجم فایل بررسی شوند.
6. برای هر asset خارجی، منبع، سازنده، شناسهٔ نسخه، مجوز، تاریخ دریافت و تغییرات ثبت شود.

## امنیت و مجوز

- هیچ installer، crack، serial، token، password یا کلید سرویس در Git ثبت نشود.
- نرم‌افزار و asset فقط از منبع رسمی یا منبعی با زنجیرهٔ اعتماد مشخص دریافت شود.
- پیش از استفادهٔ تجاری، مجوز نرم‌افزار، runtime، فونت، مدل، تکسچر، موشن‌کپچر و sample صوتی جداگانه بررسی شود.
- فایل‌های مجوز و attribution لازم در پوشهٔ `licenses/` یا فایل `THIRD_PARTY_NOTICES.md` نگه‌داری شوند.
- کلیدهای سرور و secrets فقط در متغیرهای محیطی سمت سرور ذخیره شوند؛ کد مرورگر و فایل‌های commitشده محل نگه‌داری secret نیستند.
- دادهٔ ذخیره‌شده از کلاینت قابل اعتماد نیست؛ هر عملیات آنلاین باید سمت سرور اعتبارسنجی شود.
- هیچ دادهٔ شخصی یا اطلاعات حساس شهروندان واقعی جمع‌آوری نشود. مأموریت‌های بازی در محدودهٔ خدمات مدنی و غیرخشونت‌آمیز باقی بمانند.

## ترتیب اجرایی

1. تثبیت ساختار دارایی و قرارداد export.
2. ساخت یک نمونهٔ خودرو، یک ساختمان و چند prop در Blender و آزمون GLB در Three.js.
3. ساخت یک بلوک کوچک شهر و تست کارایی.
4. اضافه‌کردن UI و صداهای اصلی.
5. ارزیابی فیزیک Rapier تنها پس از اندازه‌گیری محدودیت‌های فعلی.
6. ارزیابی بک‌اند فقط وقتی قابلیت آنلاین/حساب کاربری واقعاً وارد محدودهٔ پروژه شد.
